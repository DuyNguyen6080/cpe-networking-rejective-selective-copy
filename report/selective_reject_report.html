Selective Reject Assignment Report

Report date: May 20, 2026

Short Summary

The program in udpCode_spring26_v3 was changed into a selective reject UDP file upload. In this version, rcopy sends the file and server receives the file.

The optional flag 1 and flag 2 packets were not used.

Files Changed

File What changed
udpCode_spring26_v3/rcopy.c Added the sender state machine. It sends filename, sends data with a sender Window, handles RR and reject packets, sends EOF, and sends final DONE.
udpCode_spring26_v3/server.c Added the receiver state machine. It forks a child per client, opens the output file, stores out-of-order packets in a Buffer, sends RR or reject packets, and handles EOF.
udpCode_spring26_v3/Packet.h and Packet.c Created simple packet functions for the 7 byte header, checksum, flags, sequence numbers, and 32 bit network order fields.
udpCode_spring26_v3/Window.h and Window.c Created the sender Window. It has lower, current, and upper. The current value is the next packet to send and moves forward right after a data packet is sent.
udpCode_spring26_v3/Buffer.h and Buffer.c Created the receiver Buffer. It stores out-of-order packets, writes ready packets in order, and tracks the missing packet to request.

Assignment Rules Followed

  • Used UDP and the provided safe send/receive calls that build on sendtoErr and recvfromErr.
  • Used a 7 byte packet header: sequence number, checksum, and flag.
  • Limited data packets to 1400 bytes of payload.
  • Used flag 3 for data, flag 5 for RR, flag 6 for reject, flag 7 for filename setup, and flag 8 for filename response.
  • Used extra flags 32, 33, and 34 for EOF, EOF ACK, and final DONE.
  • Used pollCall before receive calls in the client and child receiver loop.
  • Used the required command line format for rcopy and server.
  • Kept comments simple and tied to what each function does.
  • Removed comments that sounded like outside explanation instead of student code.

Not Followed Or Limited

  • Flag 1 and flag 2 were not used because they are optional and the instruction said not to use them.
  • The Makefile was not modified. The new helper code is included from rcopy.c and server.c so the existing build file can stay unchanged.
  • The sender Window is in rcopy because this upload version has rcopy sending data. The server uses the receive Buffer.
  • The build could not finish on this machine because gcc is not installed and no WSL distro is available.
